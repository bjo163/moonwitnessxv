# MOONWITNESS XV — MASTER DESIGN
**Status: SHARED DESIGN CONTRACT & CERTIFIED DESIGN SYSTEM (@moonwitness/moonui; verified M19-32, M30-01..M30-03).**

Actual source: `packages/moonui/moon.css`, `packages/moonui/src`, Dock/HQ/Cockpit styles. Canonical MoonUI tokens include `--ink:#07060b`, `--surface:#13101d`, `--surface2:#1b172a`, `--paper:#0d0b14`, `--fg:#f7f4ec`, `--accent:#ffd400`, `--pink:#ff007a`, `--cyan:#00d4ff`, `--ok:#00e676`, `--moon:#9d4edd`, `--muted:#9e96b0`, glow tokens (`--pink-glow`, `--cyan-glow`, `--accent-glow`, `--ok-glow`), and spacing `--s1` through `--s5`. **Shared Design System semantics — MOONUI (`packages/moonui`; verified M19-32, M30-01, M30-02, M30-03; see [Components Bible](docs/design/COMPONENTS.md)).** `@moonwitness/moonui` is the sole certified design system across all MoonWitness XV surfaces. It provides:
1. **Zero-Drift Tokens (`tokens.ts` & `moon.css`)**: Typed constants and CSS custom properties enforcing uniform colors, glows, typography, spacing, and brutalist drop shadows across both React SSR and client components.
2. **Accessible Core Primitives (`feedback.tsx`, `form.tsx`, `nav.tsx`)**: High-contrast `<Tooltip>` (role="tooltip", 4-way positioning), `<Skeleton>` / `<CardSkeleton>` / `<TableSkeleton>` shimmer loaders, `<GlitchText>` chromatic aberration headings, `<CyberFrame>` tactical HUD corner brackets, `<Button>` with `variant="cyber"` and `loading` spinner (`aria-busy`), and `<Tabs>` with WAI-ARIA roving tabindex keyboard navigation.
3. **Tactile Micro-Haptics & Sensory Feedback (`client/haptics.ts`, `client/sound.ts`, `client/toast.tsx`, `client/audio-spectrum.tsx`)**: Zero-byte Web Audio oscillator clicks coupled with hardware motor vibrations (`navigator.vibrate`) for console tactility on buttons, toggles, and tabs; non-intrusive floating toasts with tone accents (`ok`, `pink`, `cyan`, `accent`); and HiDPI glowing `<AudioSpectrum>` frequency bars.
4. **Accessible Dialog Traps (`client/modal.tsx`)**: Tactile `<Modal>` and `<AlertDialog>` featuring complete Tab focus trapping, Esc dismissal, backdrop blur, and focus restoration to the trigger element upon close.

**Communication surface semantics — SKYLINK (domain D18; accepted ADR-0006, PLANNED M38; see [contract](docs/architecture/SKYLINK.md)).** The operator UI is a calm *message/transit console*, not a social feed: a three-pane inbox (channel accounts → conversations → messages), an explicit pairing panel that shows a QR only while pairing and never re-logs it, a per-channel status strip (`disconnected`/`connecting`/`open`/`logged-out`) and a delivery-attempt trail for failed sends. Queue, retry and provider error states must be named in words — no fictional `LIVE` or `NOMINAL` badges, and no green dot that means "we did not check". Inbound and outbound messages are visibly distinguished by direction and timestamp, not by colour alone. Long provider text wraps; scripture/source-language text keeps its own direction. Destructive actions (logout a paired account, delete a conversation) are confirmed and state exactly which account is affected. All primitives come from `@moonwitness/moonui` with semantic tokens; the shell keeps `id`/`en` and keyboard parity with the rest of XV.

**Storage surface semantics — ECHOLOG (domain D19; accepted ADR-0007, PLANNED M39; see [contract](docs/architecture/ECHOLOG.md)).** The storage console is a calm *archive/utility* surface, not a gallery: an object list plus a detail panel that states digest, byte size, MIME type, uploader, created time, retention deadline, legal-hold state and scan status **in words**. A `scan: skipped` object must never look scanned. Download is an explicit action that requests a short-lived grant and shows its expiry; the panel never embeds a long-lived URL. Deletion and legal hold are confirmed dialogs that name the exact object key and explain why a delete was refused (`409` reason shown verbatim, not softened). Upload state is shown as queued/verifying/committed/failed — a partially written upload is never presented as an object. No fictional `LIVE`/`NOMINAL` badge, and no green dot that means "we did not check". Long filenames wrap, RTL source filenames keep their direction, and every control is reachable by keyboard. All primitives come from `@moonwitness/moonui` with semantic tokens.

**Mission supervisor surface semantics — COCKPIT (`apps/cockpit`; accepted ADR-0008, VERIFIED M19-25–M19-30; see [ADR-0008](docs/decisions/ADR-0008-cockpit-mission-supervisor.md)).** The Cockpit is a high-density *mission supervisor and technician console*, not a consumer showcase: a brutalist split-pane operator deck comprising a microservices telemetry sidebar, six primary functional tabs (`Terminal & Logs`, `In-App Web Preview`, `Media & IPTV Player`, `Error Ledger`, `Network & Ports`, `Mission Progress`), a persistent audio/video quick-bar, and a tactile CRT phosphor shader. Full keyboard navigation is mandated: single-digit view switching (`1`–`6`), audio transport controls (`Space`, `m`, `[`, `]`, `p`), quick toggle between terminal and media (`` ` ``), and a discoverable shortcuts manual modal opened via `?`. Destructive runtime operations (`Stop All` processes, `Free Ports` killing OS port listeners) are strictly guarded by accessible modal alert dialogs (`role="alertdialog"`, `aria-modal="true"`) that trap keyboard focus and dismiss cleanly on `Escape`. The surface is fully bilingual (`id` and `en`) via an in-GUI TopBar switcher persisted in `localStorage` (`mw_cockpit_locale`), with 1:1 catalog parity across all operational texts, while preserving absolute invariance for machine service tags (`radio`, `dock`, `hq`, `ai`, `sentinel`), port numbers, raw logs, CLI commands (`moon status`, `moon free-ports`), and error log paths (`dev-errors.log`). Progress reporting reflects a read-only projection of `TODO.md` with zero invented status metrics.

**Public discovery surface semantics — DOCK (`apps/dock`; M19/M31; accepted ADR-0009).** The public surface is a moonpunk zine discovery deck, not a control room. Its entry states exactly four spaces — `READ` (`/reader`), `EXPLORE` (`/terms`), `CREATE` (`/studio`) and `SIGNAL` (`/stations`) — each rendered as a card with a 3px semantic top rule (`--accent`/`--cyan`/`--pink`/`--moon`), a MoonUI icon, a one-line human description and an arrow link. Every card states its nature in words: `REAL`, `PLANNED` or `DEMO`; `CREATE` is `DEMO` while M33 publishing is open. The display headline is `--font-display`, uppercase, two-tone (foreground plus `--pink` accent) with an eyebrow rule above it; body copy stays readable prose and never image-only. Forbidden on this surface: invented counters and `LIVE` badges, a decorative global search field without a real endpoint, the reference mockups' 13-item rail (the header nav plus `PageHeader` breadcrumbs own navigation) and the mockups' index/footer chrome. The twelve reference PNG/SVG files are **reference-only** — no reference raster, crop or derivative may be shipped as product art; see [ADR-0009](docs/decisions/ADR-0009-public-ui-reference-adoption.md) and the per-file hash ledger in [the UI baseline audit](docs/audit/ui-baseline-8737fe4.md). Reader passages keep exact edition, rights state and reproducible citation, and a withheld passage renders a denial state rather than text.


**Spatial agent-operations surface semantics — ORBIT (accepted frontend boundary, planned M40; [contract](docs/architecture/ORBIT.md)).** ORBIT is a standalone frontend, not an agent runtime or backend. Its visual direction is a futuristic moonpunk operations room with a smooth, bounded 3D scene and clear workstation/task relationships. Scene objects are navigational affordances to an inspectable 2D panel—not a substitute for timestamps or runtime state. Every initial fixture must be labelled `SIMULATED`; use `LIVE` only when an authorized read model confirms freshness, and show `STALE`, `OFFLINE`, `UNKNOWN`, `BLOCKED`, and errors in plain words. Provide a full keyboard-operable 2D list/detail alternative, reduced motion, visible focus, accessible labels, and no colour-only meaning. Load 3D client-side and lazily; measure performance and verify asset licensing before release. Use certified MoonUI tokens and `id`/`en`; ORBIT owns no identity, database, domain, approval engine, or AI executor. Consequential decisions hand off to Headquarters / 100CENTER.

**ISP operator surface — ISP Console (D20, accepted ADR-0018; planned M51; [contract](docs/architecture/ISP_NETWORK.md)).** The console is a private, bilingual Empire WORKS operations surface for ISP/RT-RW Net staff. It uses the Empire MoonUI skin with dense, readable tables and clear tenant context. Subscriber, invoice, session and network records show their owning domain, observation time and current freshness; `UNKNOWN`, `STALE`, `OFFLINE`, `PENDING` and errors are words, never color-only dots or invented `LIVE`/`NOMINAL` states. RADIUS shared secrets and service keys are never displayed after entry or returned to the browser. CoA/Disconnect and subscription termination name the affected tenant/account and require a confirmed action; delivery result, retry and audit history remain visible. The app uses server-side BFF calls to ARSY, D00 sessions and tenant grants; it has no browser-to-database path and no public Dock route. All controls use MoonUI, keyboard navigation, visible focus, reduced-motion behavior and `id`/`en` parity. Synthetic records are visibly `SIMULATED`; real network status appears only from a registered authorized probe.
