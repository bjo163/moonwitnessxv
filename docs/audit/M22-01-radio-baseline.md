## Catalog identity and seed shapes

`radio` addon defines `stations` (REST enabled, unique natural key `name`, public-readable/admin-write ACL). Seed contains 36 stations (30 Indonesia, 6 international), 35 with default `active: true` and one intentionally inactive row. Database `id`, `createdAt`, and `updatedAt` are generated by MoonQL; the source seeds do not pin station UUIDs. References from schedule/playlog resolve by `@stations:<exact name>`, so the stable compatibility identity observable in source is the station name, not a static ID.

Station fields: `name`, `streamUrl`, nullable `genre`, nullable `countryRef`, `active` (default true), nullable `lastCheckedAt`, nullable `probeOk`, `probeFails` (default 0), computed read-only `statusLabel`; standard generated `id`, `createdAt`, `updatedAt` also appear on model rows. `statusLabel` is `off` for inactive, `degraded` only when `probeOk === false`, otherwise `live`. This label is not evidence of playable/live audio: an unprobed active row also reads `live`.

Representative seeded station (the URL is deliberately withheld; this is not a tested network result):

```json
{"name":"Prambors FM Jakarta","streamUrl":"<withheld>","genre":"pop","countryRef":"@countries:id"}
```

The intentionally inactive example is `Amandit 93.9 FM` (`active:false`). `stationCatalog` selects `id,name,genre,streamUrl,status,countryRef`, filters `active:true`, expands country and orders by name. It therefore omits Amandit when the seed is applied. Its expanded relation output depends on the installed base addon/database and is not frozen as a literal response here.

## Schedule and listen fixtures

`packages/moonql-schedule/src/index.ts` defines `schedule_slots`: `title`, nullable `host`, `stationRef`, `weekday`, computed stored `dayIndex`, `startMin`, `endMin`, `live` (default true), plus generated identifiers/timestamps. It seeds 14 weekday slots, two per day, with UTC minute boundaries covering `[00:00,12:00)` and `[12:00,24:00)`. Example source row: `{"title":"Prambors Pagi","host":"Desta","stationRef":"@stations:Prambors FM Jakarta","weekday":"mon","startMin":0,"endMin":720}`. `weeklySchedule` returns projected slot fields and expands station; `nowPlaying` filters by current UTC weekday/minute and `live:true`, returning `title,host,station,startMin,endMin` with expanded station. These are schedule claims, not proof a broadcast is audible.

`packages/moonql-playlog/src/index.ts` seeds 12 `playlogs` rows over six station names. Model fields are `stationRef,event,listener,seconds` plus generated identity/timestamp; event is `start|stop|skip`, listener nullable, seconds nullable. These are synthetic demo rows, not personal listening history. Public `POST /api/v1/listen` is a beacon and stores a pseudonym rather than the supplied label; the existing privacy test exercises that behavior. Do not copy the demo listener labels to a real user playlog.

## Observed API and consumer contract

- `apps/radio/src/plugins/envelope.ts`: JSON success responses use `{ok:true,data,timestamp}`; JSON errors use `{ok:false,error:{statusCode,message,details?},timestamp}`. HTTP 204, docs, non-JSON, and streams bypass wrapping.
- Existing `apps/radio/test/stations.test.ts` asserts public `GET /api/v1/stations` is 200; anonymous station POST is 401; authenticated create is 201; malformed create is 400 with error details; deleting then fetching the row is 404 with `Station not found`; DELETE is 204. Representative success shape asserted by test: `{ok:true,data:<row>,timestamp:<ISO>}`; timestamp and DB-generated IDs are intentionally variable.
- `apps/dock/src/data/queries/program.ts` reads the `stationCatalog`, `weeklySchedule`, play count aggregates and `nowPlaying` through MoonQL SDK view outputs. Dock home payload uses `now`, `stations`, `topStations`, `perCountry`, `perGenre`, `week`, `settings`, `counts`, and `signals`; it requests catalog/week with limit 100. This confirms the consumer view names/projections, not a production response capture.
- `apps/dock/src/ui/client/Player.tsx` consumes `stationId`, `stationName`, `streamUrl`; posts `{stationRef,event:'start'}` on play and `{stationRef,event:'skip'|'stop',seconds}` on close to `/api/listen`; best-effort metadata polling calls `/api/stations/${stationId}/live-meta`. Audio element loads the passed stream URL; failures trigger a separate SomaFM ambient failover. No browser playback or external stream request was performed by this task.
- `apps/radio/src/config.ts`: `RADIO_PORT` overrides `PORT`; default `PORT` comes from `PORTS.hub` (the project contract is 3000). `RADIO_PREFIX` overrides `API_PREFIX`; default API prefix comes from core. This baseline uses `/api/v1` routes. Accepted ADR-0001 says ARSY inherits the one existing Hub at port 3000, preserving `/api/v1`, Radio domain/data, and no duplicate Hub. Physical rename remains pending.

## Limits and M28-01 readiness

Literal API response fixtures were captured from the in-memory app and normalized for generated identifiers/timestamps; stream URLs and the listen pseudonym were withheld. The captured `nowPlaying` row is a time-specific sample, while the view query and response shape are the compatibility evidence. Existing focused tests plus in-memory probes confirm public station reads, active-only catalog behavior, weekly schedule expansion, pseudonymized listen writes, missing-station 404, invalid stream URI 400, anonymous station write 401, and unsupported-route 404. Unsupported listen-event behavior remains unverified. This pinned baseline lets M28-01 compare seed/view/API compatibility; it does not prove real playback, live stream availability, PostgreSQL parity, deployment behavior, or successful physical ARSY rename. M28-01 may proceed using this reference after the artifact is reviewed and included in its working branch.
