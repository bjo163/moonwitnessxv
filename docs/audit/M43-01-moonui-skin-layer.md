## What the change does

`packages/moonui/moon.css` now carries one token layer with two self-contained skins selected by `data-skin` on `<html>`: `zine` (default, values unchanged) and `empire` (Story Universe). `apps/empire-web` pins `empire` on `/[locale]` and `zine` on the entry route, and no longer owns a palette: the `--eol-*` pseudo-skin, `data-theme="empire-story"` and 139 UI hex literals are gone. CSS-drawn artwork keeps its own colours. Details and rationale: [ADR-0014](../decisions/ADR-0014-moonui-skin-contract.md).

## Structural proof that no other primitive changed

`git diff -U0 -- packages/moonui/moon.css` reports **25 removed / 124 added lines**. The removals are exactly: two header-comment lines, the old `:root` block, the four `.m-btn[data-variant="accent"]` declarations, and the one `background` line of `.m-btn[data-variant="danger"]`. The only added declarations inside a primitive are those same five lines. **No `.m-*` rule was added or removed**, so the only route by which another app could render differently is a legacy alias failing to resolve — which the browser check above disproves.

## Limitations of this evidence

- The "before" set comes from the live production deployment rather than a locally rebuilt pre-change tree, which is admissible because `apps/empire-web/src` carried no uncommitted edits at baseline. It cannot prove anything about a build that never reached `main`.
- The other seven MoonUI consumers were not re-screenshotted. Their CSS is untouched and the token proof above is complete for the default skin, but no pixel evidence exists for Dock, Headquarters, Cockpit, Orbit, Echolog or Skylink.
- **Contrast-pair deviation from the plan.** The plan listed `on-brand/brand-2 ≥ 4.5`, which no skin can satisfy (`#f7f4ec` on `#ff007a` is 3.45:1 in zine, `#14100a` on `#db1e31` is 3.83:1 in empire) and which no primitive actually renders — `.m-btn[data-variant="accent"]` pairs `--on-brand` with `--brand`. `skins.test.ts` therefore asserts the pairs the components use: `on-brand/brand` (13.8:1 zine, 8.2:1 empire) and, for empire, `fg/brand-2-strong` (6.4:1) plus `brand-2` against the canvas at ≥3:1 for non-text accents. Zine's pre-existing white-on-pink 3.45:1 is grandfathered, not introduced here.
- Six 8-digit alpha forms of the panel surface remain literal in `apps/empire-web/src/app/globals.css` (`#111316ef`, `#111316e8`, `#111316dd`, `#11131655`, `#11131635`, `#11131629`) because they overlay artwork and `color-mix()` is only used elsewhere behind `@supports`. The spec's rule permits the nearest solid token in exactly this case; they are frozen decorative overlays, not palette declarations.
- `pnpm lint` repo-wide is red for pre-existing reasons; only the changed paths were linted.
- No commit, push, `dev`→`main` promotion or Vercel redeploy was performed at the time this note was written. That step happened later at `e740900`: see [M43-04-both-skin-release.md](M43-04-both-skin-release.md), which records the green CI run, the fast-forward of `main`, release `v2.20.0` and the live skin values.
