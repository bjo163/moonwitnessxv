A decision's acceptance does not prove implementation. ORBIT is accepted as an architecture boundary only; its app remains planned under M40. LUMEN is accepted as an architecture boundary only under ADR-0010; its package and worker app remain planned under M41. ADR-0011 keeps Dock as canonical LIGHTHOUSE runtime. ADR-0012 permits only the isolated local/CI static pilot; it does not authorize deployment, production promotion, domain attachment, or DNS changes. No separate micro-ADRs for tiny code choices. ADR-0014 adds a second skin to MoonUI; a skin selects tokens, typography roles and decorative treatment only, and may never change content, keyboard behaviour, ARIA, form meaning, rights state or the machine API. ADR-0016 records the owner's domain assignment (`a-l-l-a-h.com` → empire-web, `moonwitness.biz.id` → Dock) and requires an access tier before any hostname exists; it supersedes the custom-domain clause of ADR-0012 but keeps its single-canonical-origin rule. ADR-0017 makes `@moonwitness/moonui` the only owner of UI components, supersedes the component-placement clause of ADR-0009 §2.4, and bounds the remaining app-local components with a ratcheted exception ledger; it changes ownership, not the ADR-0014 token layer. ADR-0015 ratifies the D00/D12 reviewer-grant policy: reviewer authority is an explicit D12 scope grant bound to a D00 principal, with two-admin issuance for `approve` grants, mandatory expiry, no break-glass/delegation/machine review and fail-closed rechecks; it authorizes no schema, route, code or grant assignment.
