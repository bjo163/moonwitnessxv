# M38 — SKYLINK multi-channel communication surface

**Purpose:** build `apps/skylink` as a bounded standalone communication service owning domain **D18 Messages & Channels**, with ARSY/SIGNAL and other apps as API clients. **This is a milestone context file, not a status tracker.** Canonical source: [TODO](../../TODO.md). Decision: [ADR-0006](../decisions/ADR-0006-skylink-communication-surface.md). Contract: [SKYLINK](../architecture/SKYLINK.md).

**Gate order is deliberate:** M38-01..M38-05 upgrade the documents and the register **before** provider, storage, UI or ARSY integration work. The historical baseline had six app directories; M38-07 has added SKYLINK as a seventh health-only skeleton. A code task that treats this skeleton as complete messaging behavior or omits D18 is out of scope, not merely early.

**Exit gate:** ARSY sends and receives through SKYLINK over HTTP+WS with `SKYLINK_ENABLED=false` by default; WhatsApp (Baileys `7.0.0-rc14`) and Telegram both proven; every affected document names SKYLINK and D18; rollback to the in-process channel demonstrated with no loss of recorded D18 messages.

**Rollback:** feature flag off restores today's behaviour; the `skylink` schema is additive and never touched by MoonQL migrations.
