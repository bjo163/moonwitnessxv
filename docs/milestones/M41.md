## Outcome

Deliver a MoonWitness-owned TypeScript framework package, **@moonwitness/lumen**, plus a separately runnable internal worker application, **@moonwitness/lumen-runtime**, within the current monorepo. The framework's core agent execution loop and bounded step runner are implemented from scratch; standardized validation/testing/telemetry libraries are reused.

## Entry gates

- **M41-01 ratified (27 October 2026):** ADR-0010 is accepted by the owner, explicitly resolving the Master Vision statement to permit an internal worker process (`apps/lumen-runtime`) alongside the framework package (`packages/lumen`) without a second Hub, public task API, SQL ownership, or model router.
- Contract work must align with M29 task-lease/handoff semantics; no invented duplicate run authority.
- Live integration requires relevant M28 ARSY compatibility evidence and M29 contract evidence. Offline core/tests using fake adapters may proceed only after the architecture ratification and package/security prerequisites.
- M03 privacy/ACL and M20/37 governance/identity gates apply to restricted tools and real human approval.
- Recheck current dev SHA, existing working-tree state, package conventions, and toolchain before each implementation task.

## Product boundary

- **Framework package:** deterministic contracts, bounded agent loop, typed tools/policy, explicit workflow steps, lifecycle and adapter ports.
- **Runtime application:** a separate worker process with controlled startup, claim/heartbeat, stop/cancel and health/readiness behavior.
- **ARSY:** one API, trusted identity/authorization and canonical run/task state. No direct LUMEN DB connection or schema owner.
- **AI Gateway:** sole model/provider routing and credential boundary.
- **Headquarters/100CENTER:** human approval, review and audit owner.
- **ORBIT:** read/inspect projection; it does not execute tools or own run state.

## Non-goals for the first release

No second Hub/API, database, identity provider, Redis or queue service; no direct PostgreSQL access from LUMEN; no arbitrary shell/OS/file/browser tools; no autonomous publication; no long-term memory/vector DB; no multi-agent swarm; no exactly-once side-effect promise; no Rust rewrite without evidence; no separate GitHub repository.

## Proposed dependency order

M41-01 first. M41-02 defines the canonical boundary and types after the M29 lease/handoff contract is ready. M41-03 provides the package skeleton and ports. M41-04 (agent loop) and M41-05 (tool registry/policy) can proceed in parallel after M41-03. M41-06 adds the existing AI Gateway adapter. M41-07 builds checkpoint/lease integration only against accepted ARSY contracts. M41-08 wires approval pause/resume. M41-09 creates the independently runnable worker. M41-10 adds trace/metric/budget redaction. M41-11 runs recovery/security failure tests. M41-12 is the exact-SHA integration/release and documentation gate.

## Exit gate

M41 is complete only when every leaf task has exact-SHA evidence and human review; the package can be tested separately; the worker is independently built/deployed with a verified rollback; the live ARSY lease/status/checkpoint contracts are accepted; tool permissions and human approvals fail closed; worker-crash/duplicate-delivery/stale-lease/retry/cancel/timeout/resume tests pass; sensitive content does not leak to default telemetry; and all limitations are documented.

No checked task or passing unit suite alone certifies production. The actual deployment and rollback must be separately observed and recorded.
