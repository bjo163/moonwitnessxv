## One exact deliverable

An evidence-backed **coverage inventory**, preferably one `docs/audit/M05-08-locale-inventory.md` file (proposed path; not asserted to exist), listing every actual human-facing surface, its current language behavior and exact future owning task ID. ## Ordered steps

1. Pin `main` SHA and confirm baseline CI status; collect actual apps from `apps/*/package.json`.
2. Scan each app for hardcoded human labels, validation, loading, errors, success/empty states, accessibility names and locale choices. Include screenshots/source line references only when actually observed.
3. Record one matrix row per app with columns: interface type, existing routing, language detection/selector, current id/en coverage, hardcoded-string hotspots, proposed task IDs, tests and unknowns.
4. Inspect source-language content and stable API keys so later i18n tasks do not conflate transliteration or translated labels with authentic texts.
5. Classify result as `NOT_STARTED`, `PARTIAL`, `UNKNOWN` or `VERIFIED` **per application**, not globally. `VERIFIED` requires existing measured tests, not a selector.
6. Provide a focused negative audit: demonstrate at least one unhandled locale/missing translation, or explicitly document why no such case was found.
7. Check documentation link and source path correctness. No production build is required for a read-only inventory; if a test is run, record exact command/output.
8. Return audit filename, SHA, six-app matrix, omissions, review status and tasks now eligible (particularly M05-09).
