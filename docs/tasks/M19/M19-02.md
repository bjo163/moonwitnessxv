## Task objective and minimal grounded context

Deliver the **Dock-scoped slice** of "Define Reader/Research/Story/Operator layout/typography tokens": one documented type scale and one card anatomy used by the public surface, so display headings, eyebrows, captions and monospaced status text stop being ad-hoc inline styles. The parent row stays open — this slice covers `apps/dock` only and does not claim Reader/Research/Operator parity, and prerequisite **M19-01** (MoonUI asset-ownership audit) remains open, so no global component-contract claim is made.

Grounded facts: `apps/dock/src/app/globals.css` holds 354 `dk-*` classes with breakpoints only at 1040/900 plus reduced-motion; tokens (`--font-display`, `--font-mono`, `--s1..--s5`, palette) come from `packages/moonui/moon.css`; `pnpm ui:check` fails on arbitrary hex.

## Boundaries and work plan

1. Re-read `MASTER_DESIGN.md` §"Public discovery surface semantics — DOCK" and keep the scale semantic (no new palette, no new font family).
2. Add one `.dk-display / .dk-display-accent / .dk-eyebrow / .dk-caption / .dk-mono-status` block in `apps/dock/src/app/globals.css` using existing custom properties only.
3. Add the `.dk-space-grid` / `.dk-space-card[data-tone]` anatomy (4 → 2 → 1 columns) with `min-width: 0` and `overflow-wrap` so long copy cannot force horizontal scroll.
4. Positive test: `apps/dock/test/responsive-accessibility.test.mjs` extended to assert the three column breakpoints and that no `dk-space-card` rule sets a fixed pixel width.
5. Negative test: `pnpm ui:check` must stay at 0 violations (no raw hex, no duplicate class, no font drift).
6. Run `pnpm --filter @moonwitness/dock typecheck` and `build`; record exact commands.
7. Stop if a new token or font is required — that belongs to MoonUI and to M19-01, not to this slice.
