## Task objective and minimal grounded context

Deliver the **Dock-scoped slice** of "Implement keyboard/focus/errors/reduced motion accessibility" for the surfaces this wave touches: the four-space entry, the reader provenance disclosure and the lexicon list. The parent row stays open — HQ, Cockpit and the remaining Dock pages are out of scope here.

Grounded facts: `apps/dock/src/app/globals.css` already ships a `prefers-reduced-motion` block with `0.01ms` overrides; `apps/dock/test/responsive-accessibility.test.mjs` asserts that block statically; the mobile drawer in `ui/components/shell.tsx` already traps focus and restores it on close with `Escape`.

## Boundaries and work plan

1. Every new interactive element is reachable with `Tab` and shows a visible `:focus-visible` outline (assert the CSS rule exists for `.dk-space-card` and `.dk-provenance summary`).
2. Space cards are plain anchors — no `onClick`, no `role="button"`, no hover-only information; the status word is in the accessible text, not a colour.
3. The reader provenance control is a native `<details>/<summary>` so `Enter`/`Space`, screen-reader expansion state and focus come from the platform.
4. Error and denied states use `role="alert"`; loading uses `role="status"`; the lexicon list empty state renders catalog copy, never a hardcoded English sentence.
5. Positive test: `apps/dock/test/a11y-focus.test.mjs` — focus-visible rules present for the new selectors, `summary` is the first focusable element inside `details`, cards contain no `tabIndex` overrides.
6. Negative test: extend `responsive-accessibility.test.mjs` — `prefers-reduced-motion` still suppresses the card hover transform; and no new selector is exempted from it.
7. Run `pnpm --filter @moonwitness/dock test`, `typecheck`, `build`, `pnpm ui:check`, `pnpm exec eslint apps/dock`; record output.
8. Stop if a change would require a new MoonUI primitive; that is M19-01/M19-02 territory.
