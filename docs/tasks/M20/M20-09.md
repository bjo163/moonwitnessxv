## Task objective and minimal grounded context
Implement the pure contract fixed by [M20-08](../../design/M20-08-reviewer-grant-store-design.md) and [ADR-0015](../../decisions/ADR-0015-d00-d12-reviewer-grants.md) as `@moonwitness/review-grants`: grant/event types, lifecycle state derivation, the V1–V15 validator, `requestGrant`/`confirmGrant`/`revokeGrant`, and the read-only D08 loader. ## Boundaries and work plan
1. Keep the package pure: no database, HTTP, route, environment lookup, wall clock or randomness. Time, actor, account rows, stored grants and pending TTL are caller-supplied server-side snapshots.
2. Implement `author` single-admin issue, `approve` two-admin issue, mandatory expiry, immediate one-way revocation, explicit supersession, conflict and duplicate-live refusal, and the closed V10 lane mapping.
3. Implement the D08 loader as read-only and fail-closed: live `approve` grants only, exact domain/scope, no caller-supplied grants, no legacy `reviewer` field, unreadable store grants nothing.
4. Positive check: T1, T2, the supersession half of T10, T13 and the positive half of T16 pass.
5. Negative check: T3–T9, T11, T12, T14, T15, T17–T21 and the pending-loader case refuse without changing a grant.
6. Do not create schema, migration, route, UI, grant, principal, storage adapter or network call. Do not edit TODO status in the leaf; the integrator closes the row after review.
7. Inspect the full diff for unrelated edits, secrets, identity/API drift or content leakage.
