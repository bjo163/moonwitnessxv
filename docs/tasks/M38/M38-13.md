# M38-13 — Build the operator UI and register it in the design gates

**EXECUTABLE LEAF, NOT VERIFIED** · Priority P1 · Difficulty D3. [Canonical task state](../../../TODO.md) · [Milestone](../../milestones/M38.md).

## Objective and grounded context
The owner asked for a service with its own UI. `apps/cockpit` already proves the Fastify-serves-`dist/client` Vite pattern in this repo, and the design gates only scan registered paths — an unregistered client would bypass `ui:check` entirely.

## Boundaries
- Paths: `apps/skylink/client/**`, `apps/skylink/vite.config.mjs`, `scripts/check-ui-consistency.mjs`, `packages/eslint-config/src/index.js`.
- Colours only via `var(--*)` tokens; no drifted hex; no local clones of `ProgressBar`/`Pill`/`Tabs`.
- No fictional `LIVE`/`NOMINAL` badge; channel status must state the real state word.
- Rendering only; no mutation of provider state from a component without an explicit confirmed action.

## Work plan
1. Pin the SHA; read the cockpit client structure and the design-consistency script.
2. Build the three-pane inbox, the pairing panel, the channel status strip and the delivery-attempt list from MoonUI primitives.
3. Register the client in `MANDATORY_MOONUI_SURFACES`, `APP_STYLESHEETS` and the scan glob; add the client to the react-hooks lint block.
4. Wire the UI to the WS events and REST reads with abortable requests and explicit error states.
5. Positive evidence: `pnpm ui:check` reports zero violations and the panel renders against a running service (screenshot).
6. Negative evidence: keyboard navigation reaches pairing/channel controls, and destructive actions require confirmation.
7. Verify no hardcoded hex and no unscoped class that duplicates a MoonUI primitive.
8. Stop BLOCKED if the API contract is not yet stable.

## Rollback
Remove the client and the gate registrations; the service keeps its API.
