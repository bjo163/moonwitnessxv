# M39-09 — Publish REST upload/meta/download/delete/GC with two auth modes and hard limits

**EXECUTABLE LEAF, NOT VERIFIED** · Priority P0 · Difficulty D4. [Canonical task state](../../../TODO.md) · [Milestone](../../milestones/M39.md).

## Objective and grounded context
The driver proves storage; the surface proves safety. ARSY sessions are opaque database tokens, so the operator mode must validate upstream; the service mode uses a scoped key. Limits must fail with the right status, not a generic 500.

## Boundaries
- Paths: `apps/echolog/src/modules/*`, `apps/echolog/src/auth.ts`, `apps/echolog/src/limits.ts`.
- Two authorization modes per route: `x-echolog-key` and `Authorization: Bearer <ARSY session>` (short cache). No cookies, no login endpoint.
- Presigned downloads only; TTL ≤5 minutes; never logged.
- No driver credentials or object bytes in any log line.

## Work plan
1. Pin the SHA; read the driver contract, the ARSY session resolution and `docs/architecture/ECHOLOG.md`.
2. Implement `POST /api/v1/objects`, `GET /:key/meta`, `GET /:key`, `DELETE /:key`, `POST /api/v1/gc`, `GET /health`, `GET /health/ready` with response schemas.
3. Enforce size cap and MIME allow-list before commit; sanitize filenames for `Content-Disposition`.
4. Positive evidence: an authenticated upload returns a key and a matching sidecar; download returns a working grant.
5. Negative evidence: 401 without credentials, 401 with an expired session, 413 over the size cap, 415 on a disallowed MIME, 409 on a held delete.
6. Verify logs contain no token, no grant URL and no payload.
7. Confirm the `fs` stream path cannot escape the storage root (`..`, absolute paths, symlinks).
8. Stop BLOCKED if ARSY session validation cannot be reached; do not stub it silently.

## Rollback
Revert the routes; the driver and stored objects remain.
