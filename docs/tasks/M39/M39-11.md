# M39-11 — Document the consumer handoff, build the operator UI and register the design gates

**EXECUTABLE LEAF, NOT VERIFIED** · Priority P1 · Difficulty D3. [Canonical task state](../../../TODO.md) · [Milestone](../../milestones/M39.md).

## Objective and grounded context
The first consumers are SKYLINK attachments and, later, Dock posters and Corpus source bytes. Without a written handoff they will invent their own key format or copy bytes into their own storage — exactly the duplication the architecture forbids. The design gates only scan registered paths, so an unregistered client bypasses `ui:check`.

## Boundaries
- Paths: `docs/architecture/ECHOLOG.md`, `apps/echolog/client/**`, `apps/echolog/vite.config.mjs`, `scripts/check-ui-consistency.mjs`, `packages/eslint-config/src/index.js`.
- Handoff rule: consumers store `{object_key, digest, size, content_type}`; attachment-to-message links stay in D18.
- No drifted hex, no local clones of MoonUI primitives, no fictional `LIVE`/`NOMINAL`, `scan: skipped` never rendered as scanned.

## Work plan
1. Pin the SHA; read the contract and the design-consistency script.
2. Write the handoff section: key format, sidecar fields, upload/download calls, error codes, retention responsibilities, and what a consumer must **not** do.
3. Build the object list + detail surface (digest, size, MIME, retention, hold, scan status, grant expiry) from MoonUI primitives.
4. Register the client in `MANDATORY_MOONUI_SURFACES`, `APP_STYLESHEETS` and the scan glob, and add it to the react-hooks lint block.
5. Positive evidence: `pnpm ui:check` zero violations and a rendered screenshot against a running service.
6. Negative evidence: keyboard reachability, confirmation dialogs for delete/hold, and `409` refusal text shown verbatim.
7. Cross-check the SKYLINK state before promising attachment handoff; if M38 has not reached its store, mark the handoff "planned" and say so.
8. Stop BLOCKED if the API contract changed during this task.
