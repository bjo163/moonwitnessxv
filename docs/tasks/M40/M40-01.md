## Objective

Create the minimal standalone Next.js frontend application at **apps/orbit** named **@moonwitness/orbit**, following current XV monorepo, Next.js, and MoonUI conventions. This establishes the independent frontend build boundary for spatial agent operations without introducing any backend, database, SQL owner, identity provider, or model router.

## Boundaries

1. Target package: `@moonwitness/orbit` at `apps/orbit`.
2. Port and topology: Dev port **3007** (`ORBIT_PORT=3007`), default URL `http://localhost:3007`.
3. Standalone Next.js frontend boundary: Zero database tables, zero SQL ownership (`drizzle-orm`, `postgres` forbidden), zero backend/Fastify duplication, zero public task execution, zero AI model router.
4. UI & design system: Grounded in `@moonwitness/moonui`, consuming shared tokens (`var(--cyan)`, `var(--pink)`, `var(--ink)`, `var(--surface)`, `var(--border)`, `var(--fg)`), zero rogue hardcoded hex.
5. Truthful status: Operates with ARSY backend offline; deterministic fixtures explicitly labelled `SIMULATED` with `OFFLINE` indicators; never presents simulated state as `LIVE`.
6. Accessible 2D fallback: Core operations (workstations, agents, task queues) inspectable without WebGL.
7. Scripts: Independent `dev`, `build`, `start`, `test`, and `typecheck` scripts; integrated into root `pnpm dev` runner and `build:web`.

## Acceptance evidence

- Positive: `apps/orbit` builds, typechecks, passes isolated unit tests, passes UI consistency checks, and runs standalone with ARSY offline.
- Negative: Rejects any database/SQL dependency; rejects direct imports from `apps/headquarters` internals; rejects unlabelled live status when backend is offline.
- Monorepo integration: `scripts/dev.mjs`, `package.json`, and central ESLint configuration updated cleanly.
