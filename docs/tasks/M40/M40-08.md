# M40-08 — Human-approval handoff to Headquarters / 100CENTER

**EXECUTABLE LEAF** · Priority P1 · Difficulty D3. [TODO](../../../TODO.md) owns status. [Milestone](../../milestones/M40.md) · [Architecture](../../architecture/ORBIT.md) · [Review-queue design](../../decisions/M20-02-role-scoped-review-queue.md) · [Prior leaf](M40-07.md).

## Objective

Give ORBIT an approval handoff that is exactly what its name says: it shows an
approval requirement only when the projected record states one, and it links to
the 100CENTER review surface through a target the server validated. ORBIT gains
no review engine, no decision path and no publication path.

## Scope delivered

1. **Handoff contract** (`src/lib/handoff/approval-handoff.ts`):
   `isApprovalRequired`, `buildApprovalHandoff`, `validateReviewOrigin`,
   `resolveReviewSurface`, `LOOPBACK_REVIEW_SURFACE`. Pure, deterministic, no
   network or database access.
2. **Server-owned review surface** (`ReviewSurface` in
   `src/lib/projections/types.ts`): resolved once from the environment inside
   `fetchOrbitOperationalState` and carried into every projection branch
   (simulated, live payload, hub-health live, unauthorized, offline, resolve
   failure). Client components never read configuration.
3. **UI wiring**: `OrbitNodeInspector`, `OrbitOperationsWorkspace` (queue row
   and task inspector) and `OrbitShellHeader` render from the handoff descriptor
   instead of raw payload truth or hardcoded `localhost` literals.
4. **Honest states**: `AWAITING_HUMAN_REVIEW` (link offered), `UNAVAILABLE`
   (session unverified or origin rejected — no link), `NOT_REQUIRED` (nothing
   rendered). Simulated fixtures keep the `[SIMULATED]` marker and state that no
   live review queue is connected.

## Boundaries and integrity requirements

1. **No decision authority.** ORBIT renders and links only. Approve, reject,
   four-eyes transition, role eligibility and publication belong to the ARSY hub
   (D12/D08) and the 100CENTER surface, per ADR-0001 and the M20-02 design.
2. **Derived from the API.** An approval notice exists only when the projected
   task has `status: 'APPROVAL_REQUIRED'` plus a non-blank action and role.
3. **Server-side denial of unusable targets.** Empty, malformed, non-`http(s)`
   and credential-bearing origins are refused before anything reaches the DOM;
   the denial code is what the UI reports.
4. **Payloads cannot steer navigation.** The review path is a constant owned by
   ORBIT; only the task id and requested role are appended, URL-encoded. No
   field of a task record is used as a destination.
5. **Frontend-only.** Zero SQL, zero tables, zero identity ownership; the single
   hub at port 3000 remains the only data authority and 100CENTER (3002) the
   only review surface.
6. **Locale parity.** Every new string is defined in `en` and `id`.

## Acceptance evidence

- Positive: approval-required record + verified session + valid surface →
  `AWAITING_HUMAN_REVIEW` with a `https://<validated-origin>/review?task=…&role=…`
  link and no fabricated decision state.
- Negative: `UNAUTHORIZED`, `OFFLINE`, `UNKNOWN` → `UNAVAILABLE`, no link;
  `javascript:` / `data:` / `file:` / credential-bearing / malformed / empty
  origins → refused with the matching denial code; a task whose payload carries
  a hostile `reviewUrl` / `href` / reason text still links to the validated
  origin only.
- Contract: no mutating HTTP call, no `approve`/`reject`/`publish` callable, no
  hardcoded cross-app `href`, no `process.env` inside `src/app` or
  `src/components`, and `src/app/api` still exposes exactly one GET route.
- Full verification: `orbit test` (69/69), `orbit typecheck`,
  `eslint apps/orbit --max-warnings 0`, standalone `orbit build`, `pnpm ui:check`,
  ARSY Radio/SIGNAL regression subset.

## Explicit non-scope

The 100CENTER queue UI and its server-side role/expiry denial are rows
**M20-06** and **M20-07**, which remain unchecked in [TODO](../../../TODO.md),
and **M37-05** (cross-app token expiry and role isolation tests) is unchecked
too. This leaf closes only ORBIT's side of the handoff: it neither claims a live
review queue exists nor implements one, and the UI states that plainly.
