# M40-09 — Cross-app auth, deployment, and extraction boundaries

**Milestone:** [M40 · ORBIT — Spatial Agent Operations](../../milestones/M40.md)
**Status:** closed for the ORBIT-side boundary (see §5 for what stays open)
**Owner:** `apps/orbit`
**Depends on:** M37-01..05, M40-01, M40-05, M40-08

## 1. Objective

ORBIT renders other people's authority. M40-09 makes that statement machine-checked
instead of asserted: one hub, one review surface, both resolved server-side; every
denial (unauthenticated, expired, forbidden, unreachable, redirected, corrupt) rendered
as an honest non-live state; no credential in a config, a log line or a built client
chunk; no database, identity or private 100CENTER import; and an artifact that builds on
its own.

## 2. Scope

1. **Boundary suite** — `apps/orbit/test/orbit-cross-app-boundaries.test.mjs` (16 tests):
   dependency allowlist, no SQL/identity artifact, import graph, env contract, denial
   behaviour against real `node:http` hub stand-ins, BFF route shape, deployment
   registration, log silence, extraction wording, and a built-bundle credential scan.
2. **Redirect refusal** — the hub probe is issued with `redirect: 'manual'` and any 3xx
   is mapped to `OFFLINE` with a named reason, so an answer that merely points somewhere
   else can never be rendered as verified live state (`src/lib/server/arsy-runtime-client.ts`).
3. **Server-only review surface** — `resolveReviewSurface`, `validateReviewOrigin` and the
   loopback default moved from the client-safe handoff builder into
   `src/lib/server/review-surface.ts`. `approval-handoff.ts` now reads no configuration and
   no origin constant; the surface arrives as projection data resolved on the server.
4. **Written env contract** — `apps/orbit/README.md` documents the closed variable set,
   which module consumes each one, the fail-closed behaviour of a conflicting hub URL, and
   the deployment registration. The test asserts the document matches the code.

## 3. Boundaries held

- ARSY (`apps/arsy`, port 3000) is the only hub. `RADIO_API_URL` and `ARSY_API_URL` are
  resolved by the shared `apiBaseUrl`; a conflict between them throws and ORBIT reports
  `OFFLINE` rather than choosing a second backend.
- 100CENTER (`apps/headquarters`, port 3002) stays the only review surface, and ORBIT links
  to it instead of becoming one: no mutating call, no decision callable, one GET-only route.
- D00/ARSY keeps identity; D12 keeps the queue; D08 keeps publication. ORBIT owns no table,
  no migration, no session and no domain number.
- Denials are stated, not hidden: `UNAUTHORIZED` for 401/403 with a `SECURITY` trace,
  `OFFLINE` for outage, refusal, timeout, redirect and corrupt input, `UNKNOWN` freshness
  whenever the read itself is unverified.
- Nothing is logged, so no URL, header or payload can echo into a log or a chunk.
- Browser code reads no `process.env`; `src/app/api/ops/state/route.ts` is the only API route.
