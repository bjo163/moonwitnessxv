# M41-02 — Specify canonical run, step and event contracts

**EXECUTABLE LEAF, NOT VERIFIED** · Priority P1 · Difficulty D3. [TODO](../../../TODO.md) owns status.

## Objective

Define the narrow typed contract LUMEN consumes for a run, a workflow version, a step, execution event, checkpoint reference, lease/fencing token, cancellation and resume. Reconcile with the ratified ADR-0010 and actual M29 lease/handoff outputs.

## Boundaries

1. Depend on M41-01 and verified M29-02/M29-05 outputs.
2. Separate canonical run status from step outcomes, trace spans and UI projections.
3. Define legal transitions, terminal states, version fields, stable step IDs, event ordering, timestamp/freshness, payload-size limits and error semantics.
4. Define lease expiry, heartbeat, fencing and stale-writer rejection. Treat a worker as untrusted once its lease expires.
5. Specify at-least-once semantics and idempotency; do not promise exactly-once arbitrary side effects.
6. Do not invent ARSY routes or directly read/write SQL tables. Record API gaps for their owner.

## Acceptance evidence

- Positive: typed fixtures cover normal, paused, resumed, failed and cancelled runs.
- Negative: invalid transition, expired lease, stale fencing token, unknown state or incompatible checkpoint version is rejected/preserved as unknown.
- Schema and compatibility tests pass for valid and invalid fixtures.

## Required report

Record exact changed paths, source/result SHA, contract decisions, positive/negative outputs, compatibility gaps, reviewer and next eligible task.
