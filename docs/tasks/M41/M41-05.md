# M41-05 — Implement typed tool registry and policy enforcement

**EXECUTABLE LEAF, NOT VERIFIED** · Priority P1 · Difficulty D4. [TODO](../../../TODO.md) owns status.

## Objective

Implement the allowlisted tool registry and pre-execution policy boundary. Tool definitions expose stable ID/version, input/output schemas, required capabilities, side-effect class, timeout, retry and idempotency rules, and approval requirement.

## Boundaries

1. Depend on M41-03; integrate the policy hook into M41-04 only through its public contract.
2. Validate tool arguments before execution and normalize/validate results afterward.
3. Derive actor, roles, tenant and capabilities from a trusted owner-supplied execution context; never trust values claimed in a model-generated argument.
4. Deny unknown tools and missing permissions by default.
5. Include no unrestricted shell, arbitrary OS process, unrestricted filesystem, browser or network tool in v1.
6. Keep approval decision storage/authorization with ARSY/Headquarters; this task only defines and enforces the precondition.
7. Do not rely on the system prompt as an authorization mechanism.

## Acceptance evidence

- Positive: an authorized read-only tool succeeds and valid arguments/result pass schema checks.
- Negative: unknown tool, malformed argument/result, missing capability and expired/invalid policy context are rejected before the side effect.
- Tests prove prompt/model text cannot elevate tool permissions.

## Required report

Record policy schema, threat cases, exact positive/negative test results, changed paths, reviewer and result SHA.
