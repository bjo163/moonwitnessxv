# M41-07 — Integrate versioned steps, checkpoints and ARSY leases

**EXECUTABLE LEAF, NOT VERIFIED** · Priority P1 · Difficulty D5. [TODO](../../../TODO.md) owns status.

## Objective

Implement the durable execution adapter only against accepted ARSY/M29 contracts. Persist step progress and resume through the canonical owner rather than creating LUMEN tables.

## Entry blockers

Live integration is **BLOCKED** until the relevant M29 lease/handoff contract evidence and M28-13/M28-14 ARSY compatibility/release gates are verified at exact SHAs. Do not work around the block by opening a direct database connection or inventing endpoints. Contract-only tests with fake adapters may proceed when M41-02 is complete.

## Boundaries

1. Use stable step IDs and explicit workflow-definition/checkpoint versions.
2. Require lease expiry, heartbeat and fencing/version checks. Stale workers must not write canonical state.
3. Save successful model/tool outputs before the next step. Resume from persisted outcomes instead of repeating completed calls after restart.
4. Classify transient/permanent errors; cap retries, deadlines and backoff. Side effects need stable idempotency keys where the receiving contract supports them.
5. Represent uncertain side-effect outcomes honestly. No exactly-once promise.
6. ARSY remains the canonical run/task state and persistence owner; LUMEN does not create tables or access PostgreSQL directly.
7. Pause releases worker capacity. Approval/input resume must create a new authorized claim.

## Acceptance evidence

- Positive: a fake-ARSY contract test completes, pauses, resumes and recovers a run using saved step output.
- Negative: expired lease, stale fencing token, duplicate claim/event, incompatible checkpoint version and failed authorization are rejected.
- After gates open, run the same tests against the real accepted API with an isolated test record; document cleanup and rollback.

## Required report

Record M28/M29 prerequisite SHAs, exact contract version, positive/negative output, changed paths, reviewer, uncertain side-effect limitations, rollback and result SHA.
