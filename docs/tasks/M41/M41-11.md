# M41-11 — Prove failure recovery and agent security invariants

**EXECUTABLE LEAF, NOT VERIFIED** · Priority P1 · Difficulty D5. [TODO](../../../TODO.md) owns status.

## Objective

Run adversarial and failure-injection tests that demonstrate LUMEN fails closed under worker crashes, duplicate delivery, stale leases, invalid tool proposals, approval mismatch and sensitive-data conditions.

## Boundaries

1. Depend on M41-04 through M41-10 and the applicable M03/M04/M28/M29 gates.
2. Test crash before and after step result persistence; record whether a repeated external action is prevented by idempotency or remains explicitly uncertain.
3. Test lease expiry, stale fencing token, duplicate events/delivery, restart, workflow-version mismatch, retry exhaustion, deadline and cancellation.
4. Test direct and indirect prompt-injection-shaped data, malformed tool arguments/output, missing capability and approval argument mutation.
5. Verify that untrusted content cannot expand the allowlist, reveal secrets or publish automatically.
6. Test log/trace redaction and per-run/per-tool budgets.
7. Never mark a test passed if the scenario was not run; record infrastructure-blocked cases.

## Acceptance evidence

- Positive: approved single-agent workflow completes, pauses/resumes, and recovers from a controlled worker restart.
- Negative: each prohibited or stale condition is rejected without unauthorized side effect; ambiguous side effects are reported as uncertain rather than falsely succeeded.
- Failure-injection outputs are reproducible and linked to the exact result SHA.

## Required report

Provide a test matrix, exact commands/output, environment, skipped/blocked cases, changed paths, reviewer, rollback and residual risk.
