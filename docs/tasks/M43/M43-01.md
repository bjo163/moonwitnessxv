# M43-01 — Record the skin contract and add the `moon.css` skin layer

**EXECUTABLE LEAF, VERIFIED 2026-10-29 at `1fa799d`.** · Priority P1 · Difficulty D4 · Owner: design system. [TODO](../../../TODO.md) owns status.

## Objective

Record the accepted dual-skin contract in ADR-0014 and add the token layer that implements it: a default `zine` block that is value-identical to the pre-ADR palette, a self-contained `empire` block, a skin-scoped body field, and two `.m-btn` variant lines wired to roles. No layout, copy, route or behaviour changes.

## Entry gates

- M42-01 is closed with exact-SHA evidence; M30-04 defines what a skin may select.
- The working tree's unrelated changes are preserved and excluded from the commit.
- No new branch is created; work happens on `dev`.

## Scope

- `:root, :root[data-skin='zine']` reproduces every pre-ADR custom property value; geometry (`--s1`…`--s5`, `--ctl`) and font stacks stay untouched apart from the added `--font-editorial`.
- `:root[data-skin='empire']` is self-contained (roles plus all legacy aliases) and declares only allowlisted properties.
- `:root[data-skin='empire'] body` replaces the pink/cyan field with the Empire field; the default body rule is unchanged.
- `.m-btn[data-variant="danger"]` reads `var(--danger)`; the accent variant's foreground reads `var(--on-brand)`. Both are value-identical in zine.

## Verification

- `pnpm ui:check` passes with zero violations.
- `pnpm --filter @moonwitness/moonui build` and `pnpm --filter @moonwitness/moonui test` pass.
- A value-level comparison of the default palette before/after shows no change.

## Rollback

Restore the pre-ADR `:root` block and the two variant lines, and delete the empire block plus its body rule. The default skin needs no consumer change.

## Required report

Exact commands run, their output, the default-palette comparison, and the list of properties declared by the empire block.
