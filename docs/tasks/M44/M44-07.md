# M44-07 — Gate Cockpit and the AI Gateway

**CLOSED 2026-10-29 AS VARIANT A (STAY DARK)** · Priority P1 · Difficulty D5 · Owner: security/platform. [TODO](../../../TODO.md) owns status. Evidence: [audit §9.1, §9.5](../../audit/M44-domain-cutover.md#91-dns-record-set).

Variant B remains unbuilt by choice: both services keep the same-machine trust model, and no M44 task depends on exposing them.

## Why this is gated

- `docs/architecture/SECURITY.md:26-31`: Cockpit binds `127.0.0.1`, has **no identity system**, and rejects non-loopback `Host`/`Origin`. It can spawn and kill workspace processes. `x-moondeck-token` is a per-boot CSRF guard, not a credential.
- `apps/aigateway/src/providers/*.ts` holds only **outbound** provider keys; nothing in `apps/aigateway/src` authenticates an inbound request.

Publishing either one unchanged would convert a same-machine trust model into an unauthenticated remote control plane and an open LLM proxy. ADR-0016 §8 therefore allows two variants, and no other M44 task depends on which one is chosen.

## Variant A — stay dark (default)

- Do not attach `cockpit.moonwitness.biz.id` or `ai.moonwitness.biz.id` in Coolify.
- Record in `docs/architecture/SECURITY.md` that the two hostnames are declared in ADR-0016 but intentionally unrouted, and why.
- M44-08 checks that both return no route at all.

## Variant B — expose behind a gate (requires the code below)

- **Cockpit**: add a `COCKPIT_PUBLIC_HOST` allow-list so the existing loopback `Host`/`Origin` predicate accepts exactly that hostname when `TRUST_PROXY` is set, and put Traefik basic-auth in front. The per-boot token, the rebinding rejection and the traversal guard stay.
- **AI Gateway**: add an inbound `x-api-key` check against `AI_GATEWAY_CLIENT_KEYS`, reject whenever `AI_ENABLED=true` and no valid key is presented, and rate-limit per key. Provider keys must never appear in a response.
- Tests to add/extend: `apps/cockpit/test/` (no token → 401, foreign Origin → 403, rebinding Host → 403, configured public host → allowed only with the edge credential), and `apps/aigateway/test/` (missing/invalid key → 401, valid key → 200, provider key never echoed).
- Update `docs/architecture/SECURITY.md` to state the new invariant instead of "never exposed publicly".

## Verification

Variant A: `curl -sSI https://cockpit.moonwitness.biz.id` and `https://ai.moonwitness.biz.id` both fail to resolve or return the edge 404. Variant B: 401 without the edge credential and without `x-api-key`; 200 only with both.

**Variant A observed 2026-10-29.** Both names return `Status: 3` (NXDOMAIN) from `https://dns.google/resolve?name=cockpit.moonwitness.biz.id&type=A` and the same for `ai`; neither appears in the Coolify `docker_compose_domains` map. `docs/architecture/SECURITY.md` already records the two declared-but-unrouted hostnames and the reason (commit `9900868`).

## Rollback

Detach the domains; both services keep working on the compose network for local operators.
